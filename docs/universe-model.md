# 全市场候选层与复利核算 · 2026-10-27

## 架构与使用

公共合约目录 → 可交易加密货币池 → 流动性与数据检查 → 因子计算与横截面排序 → 相关性约束 → 最多五个候选 → 用户加入交易池 → 原有 Trend + Carry、组合分配、入出场与全仓执行检查。

打开控制台不触发候选扫描；点击“筛选五个候选”后才开始，无需 API Key。刷新页面也不会自动扫描或展示上一轮推荐。扫描不会启动引擎或下单。已有手动标的保留，点击“把候选加入交易池”追加去重；引擎运行时需先停止再更换候选池。不因排名变化强平原持仓。目录与扫描结果分别缓存五分钟和十五分钟；过期结果、错误结果、不同扫描 ID 或配置已改变的结果不能加入交易池。刷新期间不展示上一轮候选为当前结果。

支持搜索交易所当前开放的全部 USDT 直接型永续合约；不是授权账户交易新资产，也不修改 API Key 权限。自动筛选只包含 Gate `contract_type` 标识为加密货币的合约，排除股票、贵金属、指数、外汇、商品、预上线、预市场和下架中合约。手动交易池仍可保留原先选择的贵金属等合约。全部币种可被发现，不代表所有币种都适合立即开仓。

## 固定模型 v1（无收益率调参搜索）

1. 初筛：24小时报价币成交额至少100万 USDT；有效双边报价；点差不超过5bps或现有执行配置的更严格上限。对全部通过初筛的币计算因子，没有固定币种白名单或只扫描热门前N名。
2. 数据：同一个 `as_of` 时刻，只用已收盘1H和4H K线。拒绝缺口、重复、非有限价格、非正价格、过旧数据或预热不足。最多读取每周期2000根，通常为预测缩放窗口加128根，至少600根。长期缩放窗口大于接口覆盖时并不声称完整窗口。
3. 趋势组：复用 `group_trend_forecast`；短长周期方向相同且两者强度绝对值均至少2。组值 T = (|F_1h| + |F_4h|)/2，避免把多个相近动量因子作为独立大类重复加权。
4. 路径质量组：ER_n = |P_t-P_(t-n)| / Σ|ΔP|，n为24、72根1H；Q=(ER24+ER72)/2，Q至少0.10。该过滤并不保证震荡中不亏损。
5. 执行成本组：C = -B/(σ_1h × √24 × 10000)，σ取最近168根1H对数收益标准差。B = 双边手续费 + 点差 + 双边配置滑点 + 按当前费率估计的1天不利资金费。手续费取公开基础费率与配置费率较高者，不读取账户折扣；资金费收益不计作优势，不假设未来费率不变。B不含具体下单金额对应的真实冲击，最终仍由执行层盘口保护检查。
6. 在本次通过绝对条件的币池内，对T、Q、C分别计算平均名次，再按截面均值/标准差标准化；常数列归零。Score=(Z_T+Z_Q+Z_C)/3。分数只在本次候选池内可比；它不是经过校准的概率。
7. 分数降序，币名作固定并列次序；逐个选入，要求与已选币最近168根1H收益的绝对相关系数不超过0.85，至少120个共同时间点。不满足者跳过，不放松条件硬凑五个。成本和走势相关性是不同层面；目前没有完整因子正交化或 Barra 风险模型。

以上阈值是事先固定的工程假设，未按历史收益选择。是否有经济价值须用后续真实候选快照和完整成本做前向验证。不能把今天选出的五个币套回过去，然后声称历史动态选币赚钱；历史验证需要当时完整的合约池、退市信息、报价、资金费和数据覆盖。`data/universe/<scan_id>.json` 保存当时公共目录、报价、全部合格因子行、淘汰原因和模型配置，供之后审计；它本身不是收益回测。

## 复利口径

已有引擎和回测按当时净权益计算目标持仓，CAGR原本也是几何增长率。本轮新增统一复利分解和UTC自然月表，不把仓位放大或额外乘一次杠杆。

r_t = E_t / E_(t-1) - 1
R_total = Π(1+r_t) - 1 = E_end / E_initial - 1
R_30d = (E_end/E_initial)^(30/实际天数) - 1
CAGR = (E_end/E_initial)^(365/实际天数) - 1

例如先赚10%再亏10%，总收益为-1%，不是0%。首根权益前的基数是初始资金；各自然月以上一月最后已记录净权益为基数，首尾月可不完整。30天等效值不代表真实月收益，也不是未来预测。零或负权益后几何年化无定义，新增分解返回空值；保留实际累计损失。旧回测可在读取时从原权益曲线补算分解，不改写旧JSON。

这是没有出入金的回测口径。实盘若有出入金，应先建立现金流记录再做TWR/MWR，不能直接把到账金额视为策略收益。不能将重叠滚动验证折的收益连乘，也不能将并行持仓/减仓记录的收益当作顺序账户收益。

## 界面与仓位

日常设置保留：账户连接、纸面/实盘切换、交易池、初始纸面资金、组合波动率预算、总/单标的/相关组敞口边界。信号权重、Regime、EWMAC、反向执行、缓冲阈值等不再提供日常手动调参按钮；模型参数在折叠区只读，实际成本仍可维护。

选币迭代时没有提高仓位；随后已按用户指令加入固定保证金票据，最新规则见 [仓位说明](position-sizing.md)。全仓验证、持仓归属、减平仓、日亏损熔断及盘口检查保留。趋势策略的名称不能代替风险容量和成本测试。
