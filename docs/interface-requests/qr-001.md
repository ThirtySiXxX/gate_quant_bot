## Acceptance criteria for any future adoption

- QD identifies producer/consumer files and compatibility/rollback behavior;
  QR reviews mathematical semantics; user/integrator approves the exact change.
- Corrupted artifact hash, unsupported symbol/feature identity, class reordering,
  future calibration labels, embargo violation, overlapping/expired windows and
  unavailable features are rejected by independent positive/negative tests.
- Paired evaluation uses common timestamp boundaries across assets and excludes
  labels crossing stage boundaries; extra CSV files cannot become extra assets.
- Native JSON inference matches the retained estimator on held-out samples.
  Legacy compatible behavior remains covered by existing contract tests.
- Instrument availability and model rejection reasons are visible; failure to
  load a new candidate must not disable exits or liquidate existing positions.
- Tooling review is separate from model suitability. Any new paper candidate
  requires a frozen protocol, prospective evidence, meaningful trading
  participation and explicit activation approval. Historical profits alone are
  insufficient.
