# 回测与交易引擎的共用路径

## 仓位与决策

新开仓按照当时账户净权益计算，固定保证金规则没有另设回测版本：BTC/ETH 为 5% × 200x，SOL 请求同等名义敞口、最高 100x 时换算为 10% × 100x；其他币种 5% × 20x，低于 20x 时等价换算。合约张数向下取整，风险档位、最低/最高张数和可用保证金检查由同一个 `entry_ticket` 完成。已持仓不因为下一轮信号再次追加 5%，退出按共用模型比例处理，反向先平再开。

代码职责：

| 修改内容 | 共用位置 |
| --- | --- |
| 趋势、Carry、自适应风险、已收盘信号选择 | `src/strategy_signals.py`，调用原公式模块 |
| 协方差递推与预热 | `src/vol.py::_ewma_covariance_states` |
| 择时、反向执行、缓冲、减仓比例 | `src/strategy_execution.py::decide_execution` |
| 订单动作和数量 | `src/strategy_execution.py::build_order_plan` |
| 开仓权益、保证金、杠杆与合约限额 | `src/position_sizing.py::entry_ticket` |
| 成交后的择时状态反馈 | `src/strategy_execution.py::record_fill` |
| 亏损熔断及 24 小时窗口 | `src/risk.py::daily_risk_state` |

实盘适配器负责读取账户、确认全仓、盘口保护、提交订单和实际成交回报；回测适配器负责提供历史行情、模拟成交及记账。不要在适配器中重新编写另一套交易决策。

用户于 2026-10-27 明确选择恢复旧交易规则：实盘、模拟盘与回测共同关闭日亏损熔断。共用 `RiskConfig.daily_loss_limit_enabled` 默认 `false`，旧配置缺少该字段也关闭；旧的 `daily_loss_limit_pct: 8` 数值本身不会启用熔断。关闭时清除已锁存状态，但继续统计窗口盈亏，页面显示“日亏损熔断：已关闭”。全仓验证、可用资金及数据缺失保护仍按原逻辑执行。

只有显式设置 `risk.daily_loss_limit_enabled: true` 才会使用 `risk.daily_loss_limit_pct`：触发后直到当前 24 小时窗口结束都禁止开仓/加仓，权益恢复不会提前解除，减仓和平仓仍可执行。窗口从程序启动/回测开始时算起，不是 UTC 或本地自然日。普通回测、滚动验证与参数扫描均可传入同一个 RiskConfig；网页回测会传入任务启动时的配置快照，并将其保存为 `risk_config`，包括启用状态。

`allow_increase=False` 只控制能否增加风险，不得绕过正常退出缓冲、平滑或把全平改成减仓。行情缺失导致的组合降级使用单独的 `force_risk_reduction=True`，允许立即执行模型要求的减仓，但同样不得覆盖 ATR、弱信号等更彻底的退出。两个适配器都把这两种状态传入同一个 `decide_execution`，没有各自的退出公式。

历史资金费缺失时，两条路径的 Carry 信号都为零；回测资金费成本仍可能按输入的当前费率近似，并保留警告。协方差预热统一为 20 根，每个快照只用该时点已有的收益率。

## 一致性的边界

共用代码意味着相同数据、配置、账户状态及执行时点下使用相同决策。单币回测是独立虚拟账户，无法自动等同于实盘的多币账户、其他手动持仓、挂单占用、出入金和已有策略状态。回测在短周期 K 线开盘决策，实盘按 tick 检查，行情窗口、更新时点和实时价格也可能不同。

历史 K 线不能还原逐时盘口、真实成交延迟、部分成交、网络拒单及完整全仓维持保证金/盘中强平/ADL。交易所当前风险档位只是输入快照，不等于过去每个时点的档位。实盘保留明确确认全仓及杠杆回读的保护。回测结果不能当作完全复制实盘成交或高杠杆存活率的证明。

修改共用算法后必须重新运行回测。旧结果是原版本的历史快照，不会被自动重写。

## 回归验证

`tests/test_execution_parity.py` 在合成行情及隔离纸面账户中，把历史回测与交易引擎的逐笔时间、方向、动作、数量、价格、费用和最终权益对照，覆盖 BTC/ETH/SOL、山寨低杠杆等价换算、择时开关、反向执行和熔断。它验证工程一致性，不验证策略能盈利。

同文件还检查信号和协方差无未来预热泄漏，以及“纳入管理”落盘、立即更新归属/计数、下轮同步保持归属、失败时不伪报成功。`tests/web_regressions.cjs` 验证旧轮询不能覆盖新归属、重复点击受控、失败后恢复操作。

持仓归属只在登记文件原子写入成功后发布。登记与交易所持仓同步使用同一把请求锁；前端成功后立即重新获取状态，并丢弃过期响应。

## 2026-10-27 ETH 收益回归核对

对历史任务 `4934895aa5`（90 天 ETH、初始权益 10000）与 `b5bf672025` 固定同一份行情及资金费缓存、相同策略/成本/合约档位，得到：

| 版本/规则 | 累计复利收益 | 成交条数 | 最大回撤 |
| --- | ---: | ---: | ---: |
| 修改前归档原版，未模拟日亏损熔断 | +70.141987% | 58 | 77.921461% |
| 有回归错误的共用版本，8% 熔断 | −19.083832% | 125 | 76.291783% |
| 修正退出优先级及熔断与降仓耦合，保留 8% 熔断 | +4.282557% | 56 | 77.710712% |
| 当前正式代码，按用户选择共同关闭日亏损熔断 | +70.141987% | 58 | 77.921461% |

旧版与有错误版本都被精确重现。当前正式代码直接读取共用风险配置，无需替换风险函数，58 条成交的时间、动作、方向、数量、价格与旧版逐条一致，复现 +70.141987%。最终权益为 17014.198718884527，手续费为 3512.0540971682303，均与旧版一致。因此差异不是复利公式、EWMAC、协方差修复或更换仓位导致，而是风险路径变化。

已修复的错误包括：熔断把 ATR 全平覆盖为较小减仓，以及把“停止新开仓”错误地同时用作“绕过退出缓冲、强制减仓”。修复后，剩余收益差异来自旧回测缺失的日亏损熔断，改变了后续入场时点和复利路径。用户确认后，现已在共用风险函数关闭该规则，同步改变实盘与回测的行为。

旧结果没有改写。原始归因及冻结输入位于任务工作区 `work/return-regression`、`outputs/return-regression`；本次生产代码复现脚本为 `work/circuit-disabled/verify_replay.py`，结果、输入哈希及测试日志在 `outputs/circuit-disabled`。116 项 Python 测试与 8 组前端回归通过，覆盖关闭后释放旧熔断状态、亏损后继续入场、显式重新启用及两种状态下适配器一致性。这些是历史功能归因，不是未来收益预测；本结果仍不包含完整盘中全仓强平。更新后需重新加载程序和新建回测才会使用新代码。
