# Gate.io 多资产 Trend + Carry 全仓量化策略机器人（图形化版）

基于官方 [gateapi-python](https://github.com/gateio/gateapi-python) SDK 的 USDT 本位永续合约量化交易程序。
**日常操作通过网页图形界面完成**；模型内部参数按版本管理，日常无需反复手调——
双击一次启动脚本，浏览器自动打开，之后填 API Key、选模式、调参数、加币种、启停策略、看回测，全部点鼠标/打字完成。

策略是一套分层的系统性交易框架：多资产 **趋势(Trend, 多周期EWMAC动量)**
+ **Carry(资金费率)** 信号，经过波动率归一化、预测缩放(forecast scaling)后合成，再用 **EWMA协方差矩阵**
形成模型目标及减仓比例。当前默认新开仓使用**权益5%保证金**：BTC/ETH/SOL请求200x，其余加密货币20x；SOL/山寨不足请求杠杆时提高保证金、保持等价名义金额。SOL当前最高100x时使用10%保证金。同一持仓不重复追加额度，保持全仓。完整规则见 [仓位说明](docs/position-sizing.md)。旧波动率/敞口上限不再作为实际开仓票据上限。
设计思路参考了 Moskowitz/Ooi/Pedersen 的 Time-Series Momentum 研究、Koijen/Moskowitz/Pedersen/Vrugt 的
Carry 研究，以及 Robert Carver 的开源系统性交易框架 [pysystemtrade](https://github.com/robcarver17/pysystemtrade)
的整体分层方法论（不是照抄代码，是自己按同样的设计原则重新实现，并针对 Gate 只有加密货币永续
+ 黄金/白银等少数贵金属永续合约的实际情况做了适配，比如用资金费率代替期货近月/远月价差作为 Carry 信号）。

> 当前使用 `src/systematic_engine.py` 中的系统性策略引擎。
> 旧版对冲策略、终端仪表盘和已停用模块已移出当前源码；历史实现可从 Git 历史查阅。

回测、模拟盘和实盘共用 `strategy_signals.py` 的信号计算、`strategy_execution.py` 的入出场决策与数量计划，以及 `position_sizing.py` 的固定保证金换算。调整算法应修改这些共用模块；回测任务保存策略、成本和风险配置。按用户选择，日亏损熔断在所有路径共同关闭（`risk.daily_loss_limit_enabled: false`，旧配置缺少此项也默认关闭）；ATR/弱信号退出继续使用共用模型。相同输入下的决策与数量已做逐笔对照；历史 K 线仍不能复现实盘盘口、部分成交和完整全仓强平，详见 [回测与实盘一致性](docs/execution-parity.md)。

持仓概览点击“纳入策略管理”后，成功登记会立即更新归属、持仓计数和提示，无需等待下一轮策略。登记失败会保留外部持仓状态并提示原因。

**⚠️ 重要风险提示（请务必阅读）**

- 本程序及策略仅为工程实现，**不构成投资建议**，不保证盈利，历史/模拟/回测表现不代表未来收益。
- 合约交易使用杠杆，亏损可能超出预期甚至导致爆仓，加密货币与贵金属合约价格波动剧烈。
- 波动率目标(volatility targeting)会让策略在低波动期自动加杠杆、在高波动期自动减杠杆，
  但这不等于"控制回撤"——市场剧烈波动或流动性骤降时仍可能出现明显亏损。
- 请务必先用 **模拟盘(PAPER)** 跑至少 1-2 周并结合较长窗口的历史回测观察表现，再考虑切换到 **实盘(LIVE)**。
- 申请 API Key 时**务必只勾选"合约交易+读取"权限，不要开启"提现"权限**，并绑定 IP 白名单。
- API Key/Secret 保存在本地 `data/credentials.json` 文件里（明文），不要把 `data/` 目录分享给他人或上传到任何代码仓库。
- 任何自动化交易程序都可能因网络中断、交易所故障、极端行情滑点等原因产生非预期损失，运行前请做好资金规模控制。

## 策略逻辑概述

### 1. 趋势信号：多周期 EWMAC（不是单一均线交叉）

对每个标的分别在 **1H（短趋势）** 和 **4H（主趋势）** 两个周期上，各自计算 4 组不同快慢速度的
指数加权移动均线交叉(EWMAC)子预测：`(8,32)`、`(16,64)`、`(32,128)`、`(64,256)`（数字单位=该周期的K线根数），
每组做波动率归一化：

```
Trend_{f,s} = (EMA_fast(P) - EMA_slow(P)) / sigma_P
```

`sigma_P` 是用 EWMA(λ=0.94) 估计的"每根K线尺度"价格波动，不是年化波动率，确保分子分母量纲一致。
4 组子预测按 Forecast Diversification Multiplier(FDM) 加权合并成该周期的趋势预测，再和另一个周期的
预测按 `short_trend_weight`/`main_trend_weight`（默认 0.6/0.4）合成最终趋势预测。

### 2. 大周期 Regime 过滤（1D）

用日线 EMA(21/55/200) + ADX(14) 把市场状态分类为"趋势向上/趋势向下/震荡"三类：
如果趋势预测方向和大周期 Regime 方向相反，衰减到 `regime_oppose_dampen`（默认0.5）；
如果 Regime 是"震荡"，整体衰减到 `regime_range_dampen`（默认0.8）——避免在明显逆势或无趋势的行情里满仓押注。

### 3. Carry 信号：资金费率

传统期货的 Carry 用近月/远月合约价差，永续合约没有到期日、没有这个价差，改用资金费率近似：

```
年化Carry(做多视角) = -年化资金费率(annualized funding rate)
```

资金费率为负（空头付多头）时对多头是正向 Carry，反之亦然，再除以年化波动率、做预测缩放，得到 Carry 预测。
回测会从 Gate 的历史资金费率接口分页下载逐期数据，并按时间严格因果对齐；只有下载失败或历史覆盖不足时，
才会明确给出警告并回退到实时费率近似。实盘/模拟盘每轮读取当时的实时资金费率。

### 4. 合成预测 + 预测缩放/封顶

```
F = trend_weight * F_trend + carry_weight * F_carry   (默认 0.8 / 0.2)
```

每一层信号在合成前都做过"预测缩放"（滚动窗口内 `E(|F|) ≈ 10`）和封顶（`|F| ≤ 20`），缩放窗口严格只用
截至当前时刻的历史数据（causal，不看未来），这样不同标的、不同信号来源的预测强度才有可比性。

### 5. 模型单位：波动率目标 + 相关性感知风险分配

以下是保留的模型单位，供入场过滤和减仓比例使用；`volatility`旧模式才把它直接当作实际仓位。当前`fixed_margin`默认由独立票据决定实际开仓金额。模型单位按预测强度和波动率计算：

```
raw_weight_i = target_vol * (F_i / 10) / sigma_i
```

再用 EWMA 协方差矩阵 Σ（默认按4H或1D K线计算，`covariance_interval` 可调）算组合层面的实际波动率
`sigma_p = sqrt(w'Σw)`，缩放系数 `k = target_annual_vol / sigma_p`，把整组仓位等比缩放到目标波动率，
相关性越高的标的（比如BTC和ETH）天然会因为协方差矩阵的作用被分配到更小的独立权重（组合层面已经有分散化收益）。

然后依次应用硬约束（超出则等比或分组缩小）：单标的敞口上限 `max_instrument_exposure_pct`、
同相关分组敞口上限 `max_correlated_group_exposure_pct`、组合总杠杆上限 `max_leverage`。

### 6. 调仓缓冲区（降低换手/手续费磨损）

只有当"目标仓位"和"当前仓位"的差值超过 `no_trade_buffer_pct`（按满预测F=10时对应的仓位规模折算）才会真正调仓，
避免预测值小幅波动就频繁开平仓被手续费和滑点"磨损"掉利润。

## 回测（网页"回测"页）——组合级，不是逐标的分开测

在正式跑模拟盘/实盘之前（或者实盘正在运行的同时），可以在网页"回测"页用真实历史K线检验策略表现：

1. 勾选想测的标的（默认=当前配置的全部交易标的，可取消勾选，也可以在"额外标的"里临时加测没配置过的标的）、
   回测天数（预设按钮：30/90/180/365天，或直接改数字），初始资金留空则用当前"策略核心参数"里的值，点"▶ 开始回测"。
2. 任务在后台线程运行，不会卡住网页，也不会影响正在运行的实盘/模拟盘引擎——**两者完全独立，互不干扰**，
   可以放心地一边跑实盘一边跑回测。下方"回测任务"列表会显示进度（下载数据 → 回测计算 → 完成）。
3. 这是**组合级**回测：一次任务对你选的整组标的**同时**跑，直接复用生产环境的
   `vol.py`/`trend.py`/`carry.py`/`portfolio.py`/`backtest.py` 判定逻辑（和实盘/模拟盘完全一致，不是另外写的简化近似版），
   输出的是**组合层面**的权益曲线和统计指标，而不是把每个标的分开单独测。
4. 点任意一条任务可以查看完整结果：CAGR(年化收益率)、年化波动率、Sharpe、Sortino、最大回撤、Calmar、
   年化换手率、交易数、权益曲线图、分标的贡献（每个标的的净盈亏/手续费/资金费/最新预测值）、逐笔交易明细。
   任务历史会保存在 `data/backtests/`，重启程序后依然能看到。

**关于回测的几点说明（务必了解，避免误读结果）：**

- 组合协方差矩阵在回测里用 O(n) 的一次遍历预先算出"逐时间点快照序列"，再用因果(asof)查找定位到每个决策
  时刻对应的快照——这是性能优化，不影响正确性（只用过去数据，不看未来）。
- 主时间轴按"短趋势周期"(1H)walk，而不是逐15分钟走查——因为信号管线里没有任何东西比1H变化更快，
  这样做和逐15分钟走查在行为上完全等价，但快得多，验证过3标的×150天数据能在3秒内跑完整个回测。
- Carry 信号和资金费成本优先使用**逐期真实历史资金费率**；下载失败或历史覆盖不足时会在结果中警告，
  并仅对缺失部分回退到实时费率近似。
- 历史K线会按"合约代码+周期"缓存在 `data/klines/`，同一标的重复回测只需要补最新一小段数据，速度会快很多；
  如果怀疑缓存数据有问题，直接删除 `data/klines/` 目录里对应的 CSV 文件即可强制重新下载。
- Gate 交易所K线历史接口本身有约10000根的深度上限，程序会自动按周期换算成天数上限并提前裁剪你填的回测天数，
  超限会在回测结果的"警告"区提示，不会导致任务直接失败。
- 和所有回测一样，**历史表现不代表未来收益**，交易笔数太少时统计结果参考意义有限，建议结合较长的回测窗口
  和后续模拟盘的实盘运行数据一起综合判断；也建议在"更换标的池/大幅调整核心参数"后都重新跑一遍回测。

## 策略核心参数含义（模型内部参数仅只读展示）

下表的波动率及组合敞口上限约束模型单位；固定保证金模式的实际开仓量见本文开头和[仓位说明](docs/position-sizing.md)。

| 参数 | 含义 |
|---|---|
| 模拟盘/回测初始资金 | 仅 paper模式/回测 默认初始资金，live模式直接用账户真实权益 |
| 趋势/Carry信号权重 | 最终合成预测 F 里两类信号的权重，默认 0.8/0.2（趋势为主导，carry 权重调低是为了在强趋势期间不被稀释） |
| 短趋势(1H)/主趋势(4H)权重 | 趋势预测内部两个周期的权重，默认 0.6/0.4（1H权重调高，让策略更快响应新趋势的启动） |
| 组合目标年化波动率 | 整个组合缩放的目标，越高整体仓位越激进 |
| 组合总杠杆上限 | 硬约束，防止极端行情下杠杆失控，默认4倍 |
| 单标的敞口上限 | 防止单一标的过度集中，默认55% |
| 相关分组敞口上限 | 防止"表面上分散实际高度相关"的标的（如BTC/ETH）过度集中 |
| 调仓缓冲区 | 越大换手越少，越省手续费，但对信号变化的响应也越慢；开仓/加仓使用该阈值，默认25% |
| 减仓/平仓缓冲区倍数 | 同方向减仓或平到0使用“调仓缓冲区 × 倍数”，默认3倍；极端自适应降风险可绕过放大的退出缓冲 |

## 手动筛选与模型参数管理

点击“五币推荐”页的“筛选五个候选”按钮后，扫描 Gate 当前可交易的加密货币 USDT 永续合约，按趋势强度、路径质量和执行成本排序，再检查候选之间的相关性，展示最多五个候选。无需API Key；打开或刷新页面不触发推荐，也不会自动开仓。可以手动搜索添加其他合约，也可在引擎停止时把本次候选追加到交易池；已有手动标的不会被删除。不足五个合格候选时允许空缺。

日常表单保留模拟初始资金和实际成本，仓位规则直接展示。趋势权重、Regime、EWMAC与缓冲区等模型参数放到折叠区只读。当前默认已按用户指令提高新开仓额度；没有依据历史收益重新优化模型参数。

原有回测已按净权益调仓并计算CAGR；现在增加UTC自然月复利表。总收益使用 `期末净权益/初始资金-1`，等价于账户分期收益连乘；不能累加每笔交易或每月收益。历史任务从已有权益曲线补算显示，不改写旧文件。

研究依据、固定公式、来源限制和验证边界见 [全市场候选模型说明](docs/universe-model.md)。当前评分是相对适配度，不是已验证收益预测；禁止用今天的候选池倒推历史动态选币绩效。

## 🔒 程序能动哪些仓位（账户接管边界）

**程序默认只管理它自己开过的仓位。** 引擎每次开仓都会把这笔仓位登记下来（存在
`data/owned_positions_<模式>.json`，重启不丢），此后只有登记在案的仓位才会被调整或平掉。

交易所上其它持仓——你在 Gate 网页手动开的、别的程序开的、用本项目"手动开单"页测试开的——
一律被标记为**外部持仓**：

- 程序**不会**平掉、加仓、减仓或反向它们；
- 该标的会被**整体跳过交易**。双向持仓模式下，策略若在同一标的同方向开仓会和你的仓位合并成
  同一条腿，之后策略平仓就会把你的仓一起平掉，所以在你明确表态前程序完全不碰这个标的；
- 控制台「当前持仓」表会把它们标成"外部持仓"，并在表格上方给出提示条。

想让策略接管某笔外部持仓，在该行点「纳入策略管理」，二次确认后下一轮生效。想恢复旧的
"启动即接管整个账户"行为，把 `systematic.manage_existing_positions` 设为 `true`（不建议）。

**从标的池移除某个标的后**，它的遗留持仓不会再收到任何调仓/退出指令。程序不会自动平掉它，
而是在控制台标记为「待确认平仓」，由你点「确认平仓」再执行，或者把标的加回标的池恢复管理。
需要自动清仓请设 `systematic.auto_close_removed_symbols: true`。

## ⚠️ 反向执行（人工干预开关）

"设置页 → ⑤ 反向执行"是一个实验性的人工干预开关，默认关闭。开启后，预测计算、波动率归一化、组合风险分配、
杠杆/敞口约束和调仓缓冲——**全部照常按原来的逻辑计算**，只在最终真正下单这一步，把方向对调：算出来该
开多，实际执行开空；算出来该开空，实际执行开多。平仓方向由持仓方向决定，也会自动跟着倒过来。

这不是"模型认为反过来更对"，纯粹是给你一个人工干预的手段——如果你观察到某个标的池/参数组合下，策略的
判断持续和实际走势相反（这种情况理论上不该系统性出现，但不排除某些市场阶段/参数组合下确实如此），可以用
这个开关快速验证"反过来做"是不是真的更好，而不用重写一遍信号逻辑。

**务必先在"回测"页用相同的标的池和参数验证过"反向执行"确实表现更好，再考虑在模拟盘/实盘打开它**，否则很
可能只是把亏损方向从"做多"换成"做空"而已，本质没有解决问题。开启后仪表盘标题栏和"K线图"页面都会有醒目的
⚠️ 提示，运行日志里每次调仓也会同时记录"计算方向"和"实际执行方向"，避免你忘记这个开关是开着的。

## 滚动样本外验证 与 趋势捕获诊断

回测页勾选"同时做滚动样本外验证"后，除了常规结果还会多出两块内容。

**趋势捕获诊断**（每次回测都会自动做）自动识别行情里幅度≥8%的显著趋势段，逐段打分，
用来分辨"到底是漏趋势，还是抓到了但拿不满"：

| 指标 | 含义 | 怎么读 |
|---|---|---|
| 参与率 | 有多少趋势段我们有仓位 | 低 = 真的漏了趋势 |
| 捕获率 | 行情动了X%，账户赚了Y%，Y/X | 参与率高但这个低 = 方向对但仓位太小 |
| 入场滞后 | 趋势走了百分之多少才进场 | 高 = 入场太慢 |
| 离场过早 | 趋势还剩百分之多少就走了 | 高 = 拿不住 |

**旧版波动率模式的合成数据诊断（不代表当前规则或真实行情）**：在合成的多段趋势行情上跑这个诊断，结果是参与率100%、
入场滞后中位数只有5-6%、离场过早0%，但捕获率中位数只有26-33%。也就是说策略方向对、
进场早、也拿得住，**真正的瓶颈是仓位规模而不是择时**。原因是波动率目标：单标的权重
≈ 目标年化波动率 ÷ 该标的年化波动率，15%的目标除以加密资产60%左右的波动率，本来就
只有约25%的仓位——捕获率大约就等于这个比值。所以想吃到更多，主要的杠杆是
`target_annual_vol_pct`，而不是继续改入场/出场逻辑。

⚠️ 但上面这个结论是在**合成数据**上得到的，合成行情的趋势比真实市场干净得多。
请务必在你自己真实的标的池和历史上重新跑一次诊断再下判断——这也正是把它做成常驻工具
而不是一次性分析的原因。

**滚动样本外验证**把窗口切成若干折分别统计。看的时候**不要只看均值**，要看各折之间的
离散程度、正收益折数占比、最差一折有多差。如果只有一两折特别好、其余平平，说明整体
收益是被某段特殊行情撑起来的。

需要说明清楚的是：本策略的参数是人工设定的、不是从数据里拟合出来的，所以这里做的是
**跨时间稳定性检验**，不等于"已经做过防过拟合验证"。以后如果真的引入需要训练的模型
（比如概率型反转分类器），必须在这个框架上再加 purged & embargoed 的交叉验证，
否则三重屏障标签的窗口重叠会造成训练集/验证集泄漏，回测会好看得离谱而实盘失效。

`src/walkforward.py` 里还有 `parameter_sweep()`，可以扫描单个参数看收益/Sharpe曲面。
判读原则：曲面应该是平滑的小山包，而不是某个取值上的孤立尖峰——尖峰几乎必然是拟合了
历史噪声。目前对 `target_annual_vol_pct` 扫描出来的曲面是平滑单调的，属于健康形态。

## 交易标的与黄金

网页"设置 → 交易标的"里可以自由输入任意 Gate.io **USDT 本位永续合约**代码，不做限制。
黄金对应合约代码为 `XAU_USDT`（Gate 贵金属永续合约区，白银为 `XAG_USDT`）。
Gate 的贵金属合约本质仍是"永续合约"，通过资金费率机制模拟24小时连续交易，
和外汇/CFD 平台按自然日收取隔夜利息(overnight swap)的机制不同，但效果类似，程序统一按资金费率处理。
具体合约代码是否仍然上线交易，请以 Gate 官网合约列表为准。

策略引擎全程只在**同一方向**持有单一仓位（不会同一标的同时开多又开空），账户仍运行在 Gate 的
"双向持仓模式(dual mode)"下（引擎启动时会自动尝试切换，切换前提是该结算币种下没有任何持仓/挂单），
只是这只是账户层面的模式设置，新策略本身不使用"同时对冲两条腿"的逻辑（那是旧版策略的做法）。

## 局限与后续可做的事（当前版本范围）

当前版本交付的是可运行的研究框架（信号生成→组合风险分配→执行→组合级回测）。以下部分仍有限制：

- **历史资金费率覆盖**：正常情况下使用逐期真实历史费率；接口失败或可用历史不足时，缺失区间会警告并退回实时费率近似。
- **Forecast Diversification Multiplier / 协方差**：当前是简化版实现（滚动相关性/EWMA协方差），
  没有做 Ledoit-Wolf 收缩估计等更稳健的协方差估计方法。
- **压力测试套件**：已有单参数扫描和滚动分折统计，但还没有把成本翻倍、波动率冲击和多参数扰动整合成一键式套件。
- **Walk-Forward 的范围**：当前功能用于跨时间稳定性检查；参数不是从样本内自动拟合，
  因此不等同于带 purging/embargo 的完整模型训练验证流程。
- **蒙特卡洛/Bootstrap 检验**：没有做收益率bootstrap重采样、P(最大回撤>30%)、P(收益<0)等统计量。
- **动态信号权重**：趋势/Carry权重目前固定为0.8/0.2，没有做样本内优化或自适应调整。

这些限制不妨碍框架运行，但现有测试和回测也不构成盈利有效性证明；请把本项目视为研究与工程基线。

## 常见问题

- **为什么模拟盘也需要真实 API Key？** 模拟盘只用 API Key 读取公开行情（K线、价格、资金费率、合约参数），
  不会用来下单或访问账户资金，用真实数据模拟是为了让表现尽量贴近真实市场磨损。
- **切换双向持仓模式失败怎么办？** 最常见原因是账户里还有旧的持仓或挂单，去 Gate 官网合约页面手动平仓/撤单后，
  回到网页点"停止引擎"再"启动引擎"重试。
- **改了设置页的风险边界没生效？** 这些值是热更新的，等下一次tick（默认15分钟内）就会用上新值；模型内部参数已移出日常编辑表单。
  但"运行模式"和"API Key"的修改需要手动点一次"停止引擎"+"启动引擎"（因为要重新建立交易所连接）。
- **为什么某个标的一直没有仓位/信号？** 可能是该标的对应周期的历史K线数不足 `min_bars_short`/`min_bars_main`/
  `min_bars_regime`（数据不够可靠时会跳过该标的），也可能是波动率目标+相关分组约束把它的权重压得很小，
  属于正常的风险分配结果。


### 2026-09-06 收盘时机模型（当前默认仅 ETH_USDT）

在原有趋势、Carry 与波动率仓位模型之后加入共用的执行时机模块：短期价格恢复连续两根确认、短长趋势同向入场、噪声中的偏离过滤、弱信号持续退出、反向先平后开、同根信号避免重复追单，以及盈利后的 3 ATR 收盘跟踪退出。同向一般调仓执行目标差额的一半；确认退出和风险降级减仓不打折。跟踪退出只在引擎运行并获得新收盘K线时执行，并非交易所原生止损单。

`systematic.execution_timing` 可配置以上规则；`enabled: false` 可关闭时机层，`symbols: [ETH_USDT]` 限定启用范围。未显式配置时采用该 ETH 默认方案。其他币种尚无一致改善证据。策略状态按 paper/live 独立持久化，重启保留确认与跟踪数据。首次升级接管已有仓位时，如没有该仓的时机历史，ATR 盈利跟踪不会追溯恢复；趋势反向和弱信号退出仍生效。

每次开仓或加仓必须回读并明确确认 `verified=true` 且 `margin_mode=cross`；逐仓、未知模式或校验失败均拒绝新增风险，减仓和平仓不受模式校验阻挡。全仓会共同使用账户抵押资产，分配 5% 初始保证金不等于最大损失仅 5%。本轮未将仓位放大到 5% 保证金 × 200x。

Carry 改为基于历史已结算费率归一化（无历史时置零并记录提示）；协方差按 K 线时间戳对齐，避免不同上市时间的币种按行号错配。回测包含手续费、滑点及近似资金费，使用已收盘信号在下一根开盘成交；不包含全仓维持保证金阶梯、真实标记价格强平、盘口成交和日内跳空的完整仿真，不能作为高杠杆可行性证明。样本筛选是探索性比较，尚未获得未接触数据的独立前瞻验证。
